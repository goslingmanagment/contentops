# ContentOps

Учёт и оборот контента агентства: каталог, забор с Я.Диска, план, размещения и сверка с
Agency Hub (`README.md`, `PRD.md`).

- **Язык документов — русский, без жаргона.** Происхождение (не lineage), забор
  с диска (не ингест), дубли (не дедуп), обкатка (не staging), превью (не прокси).
  Английский — только для кода, команд, названий продуктов (Docker, Tailscale,
  Agency Hub) и ID (`PPV-073`). Имена файлов — по смыслу (`naming.md`), а не по
  фазе процесса («бриф», «синтез», «обзор»).
- **Состав репо фиксирован:** `README.md`, `AGENTS.md` (общие инструкции для агентов), `PRD.md` (зачем), `SPEC.md` (как
  устроено; §13 — открытые вопросы), `PLAN.md` (этапы 1–10), справочники
  `docs/reference/{naming,legacy-and-import,infrastructure,compression,schema,hub-media-discovery}.md`
  (у последнего папка улик `hub-media-discovery/`; `annotation.md` появится на этапе 8а),
  итоги слепого просмотра `docs/blind-2026-09-06.json.gz`, `tools/`, `design/` (образец
  интерфейса 1б: `DESIGN.md` и прототип на стеке SPEC, принят 28.09.2026; первый PR 1а
  переносит прототип в корень, образец сохраняет тег `design-1b`) и код
  продукта в корне: `apps/`, `packages/`, `ops/`, `Dockerfile`, `docker-compose.yml`,
  `.env.example`, `.github/` (CI), файлы pnpm workspace (решение владельца 30.09.2026).
  Новых каталогов под процесс (`plans/`, `evidence/`, `decisions/`, брифы, обзоры) не
  заводить; черновики и пробы — в scratchpad, не в репо.
- Норма — PRD/SPEC/PLAN и разделы справок, на которые они прямо ссылаются как на
  правило (naming §1–9 и §11 — приложение SPEC; `schema.md` — задание на миграции,
  при расхождении побеждает SPEC); `design/DESIGN.md` — принятый образец интерфейса;
  остальное в `docs/reference/` — датированные факты, замеры и обоснования.
- Продукт делается целиком, продуктовых волн нет (PRD §1, PLAN). С 1а продукт работает
  в ВМ Hyper-V `contentops` на winpc (вход `ssh contentops-vm`, доступы —
  `~/code/8-docs/server-inventory.md`): до этапа 3 — тестовые прогоны, с этапа 3 — живой
  экземпляр с настоящей базой; затем переезд на сервер (PLAN 9б–10). ИИ и автоматизация
  агентами — этап 8, после загрузки партии библиотеки; обкатка и полная приёмка — 8г,
  остаток библиотеки — 9а, отката на winpc нет (решения 12–13.09.2026); до ИИ работают
  импорт, ручные поля и общий API.
- Хостинг решён: всё локально, внешнее — только бэкап
  (`docs/reference/infrastructure.md` §1). Провайдеров не предлагать.
- **Код:** сейчас код — прототип в `design/` (`pnpm install --frozen-lockfile`,
  Docker не нужен); после переноса workspace в корень на этапе 1а — в корне, тестам
  с базой нужен запущенный Docker (Testcontainers). На winpc разработка — только в WSL
  (потолок 2 GB: T3 и лёгкие агенты); сборки и тесты — на Mac и в CI. Локально — только
  тайпчек, линт и тесты затронутого пакета (`pnpm --filter <пакет> typecheck`, `… test`,
  `pnpm biome check <пути>`). CI — GitHub Actions на GitHub-hosted `ubuntu-24.04` с
  первого PR 1а: `pnpm check` (тайпчек, Biome, тесты, Testcontainers). Тесты, названные
  в PLAN, SPEC и схеме §9.4, — норма и пишутся вместе со своим этапом. Auto-merge
  выключен: код — в своём worktree, одна задача — один готовый PR, сливай сам после
  зелёного CI (`gh pr merge --squash`). В описании PR — какие пункты «Готово, когда»
  PLAN закрыты; подэтап закрывает владелец. Правки только документов — сразу в `main`.
- **Как увидеть:** `pnpm dev` → `localhost:5173/#/lora/library`, роль —
  `?as=km|owner|reader`.
- **Выкатка:** до этапа 3 — нет; с этапа 3 — в ВМ из тега.
- **Опасно:** копия Я.Диска на winpc (и через `/mnt/c` из WSL) — ничего не удалять, не
  переносить и не переименовывать: уедет в облако при следующем запуске клиента;
  `drizzle-kit push` — схема меняется только миграциями; агенты и тестовые стеки в ВМ
  пилота не запускаются: с этапа 3 там единственная настоящая база, бэкапа нет.
- **Грабли:** маршрут вида `{id}:verb` (таблица маршрутов в `packages/contracts`)
  Fastify 5 не разбирает — `/:id::verb` даёт один параметр `id::verb`; преобразователь
  маршрутов пишет `:id(^[^:/]+)::verb`.
  Настройки Tailwind 4, Drizzle и Vite — в их конфигах, образцов здесь нет.
- Код следует PRD/SPEC/PLAN и `design/DESIGN.md`; расхождение — вопрос владельцу в PR,
  норму без его просьбы не править.
- **Репо публичное** (с 29.10.2026). Медиа моделей, имена фанов, ключи и выгрузки с
  дисков и из Hub в git не класть (медиафикстуры без людей — можно): снимки Я.Диска — в
  `~/Documents/contentops/ydisk-snapshots/` на Mac. История до 29.10.2026 и PR #1–#4 — в
  закрытом `goslingmanagment/contentops-archive`.
- **Миграции** — по этапам (`docs/reference/schema.md` §9.5). До тега `schema-freeze`
  (первый день этапа 3) файлы правятся на месте, тестовая база пересоздаётся заново;
  после — только новые файлы вперёд. `schema.sql` и зеркало Drizzle (`drizzle-kit pull`)
  порождаются из миграций в том же PR, что и миграция; руками не правятся.
